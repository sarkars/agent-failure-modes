**Frequency**: Common

## Issue: AI-built web pages default to purple gradients and frosted-glass cards. Give the tool brand tokens and check every generated screen before you ship.

> **One line:** You ask an AI tool for a landing page and get the same indigo-to-purple hero and translucent "glass" cards as every other AI demo, often with text that is hard to read on the glass; the fix is to hand the tool your palette as tokens and run a check that flags off-token colors, decorative gradients and glass under text before merge.

## 1. In plain words
When you give an AI tool a vague request like "build a landing page", it fills every blank with the most common answer it has seen. For color, that answer is often an indigo-to-purple gradient on white, plus see-through "glass" cards. The page works, but visitors recognize it as AI-made, and text on the glass can be hard to read.

## 2. What it looks like
**Without the fix** (builder prompting an AI tool, no review step)
```
Builder: Build a landing page for Ridgeline, a bookkeeping app for Denver contractors.
Tool:    Done. Hero: gradient from-indigo-500 to-purple-600, centered white headline.
         Features: three cards, bg-white/10 backdrop-blur-lg, white body text.
         Pricing: the same glass cards, sitting over the gradient.
Builder: Looks modern. Ship it.
         (No contrast check runs. On the pricing card, "$29 per month, billed yearly"
         sits on the lightest part of the gradient. The client says it looks like
         every other AI demo they have seen.)
```
**With the fix** (palette given up front, checker runs before merge)
```
Builder: Build a landing page for Ridgeline. Use only the tokens in tokens.css:
         --ink #1B2430, --paper #F2F4F5, --brand #0F5E8C, --accent #C2410C.
         No decorative gradients. No translucent fill under text.
Tool:    Hero: --paper background, --ink headline, one --brand button.
         Pricing cards: opaque --paper fill, 1px --ink border, --accent price tag.
Checker: 0 colors outside tokens. 0 gradients. 0 backdrop-filter.
         Every text pair measured: lowest is above 4.5:1. Pass.
```
The tool got a palette instead of a blank, and the checker measured the result instead of trusting the screenshot.

## 3. Why it happens
- **The most common color wins.** Anthropic calls this distributional convergence: with no direction, the model samples from the high-probability center of web training data. One developer's essay traces the purple to Tailwind UI demos that used `bg-indigo-500` (secondhand; section 4).
- **The prompt leaves color and surface free.** Builders ask for "a modern landing page" with no palette, token file or brand guide, so the tool has nothing to override the default.
- **Nothing measures the result before merge.** Generated code builds and lints cleanly. No step flags raw color utilities or measures text over translucent layers, and the glass looks fine in the one screenshot the builder checks.

## 5. The fix
**The principle:** Never leave color and surface to the tool's default; give it your tokens, and measure what comes back.

**Do this**
1. **Give the palette before the first prompt.** Put 4 to 6 named hex values, or a path to your token file, in the prompt or the project rules file (for example a Cursor rules file or `CLAUDE.md`).
2. **Every color comes from a token.** Generated code uses no raw hex or color utilities (`indigo-*`, `violet-*`, `purple-*` or any other) that are not mapped to a token.
3. **A gradient needs a stated job.** Keep a gradient only if it is a brand asset or serves a named purpose, and record that in the PR note. Decorative gradient washes are removed.
4. **No body text on glass unless it measures.** Text on a translucent or gradient layer must pass 4.5:1 (3:1 for large text) at its worst sampled point, not its average.
5. **Every glass layer has an opaque fallback.** Provide a solid fill under `@supports not (backdrop-filter: blur(1px))` and under `prefers-reduced-transparency: reduce`, and make the solid fill the default for text-heavy panels.
6. **Run the check on every generated screen before merge.** Log each flag with the screen, the rule and the outcome (fixed, kept with reason, sent to a designer).
7. **Watch for the second default.** After you ban purple, check whether the tool swapped in another stock look (Anthropic's skill names cream with terracotta, and near-black with one acid-green accent). The same rule applies: off-brief, off-token means flagged.

**Reference design: project rules block** (paste into the tool's project instructions)
```
Use only the color tokens in styles/tokens.css. Do not add hex values or color utilities that are not tokens.
Do not add decorative gradients. Use a gradient only when the brief or a token names one.
Do not put body text on translucent or blurred layers. Panels with text use an opaque token fill.
If no palette is given, ask for one before generating, and say which defaults you are avoiding.
```

**Reference design: review checklist** (one row per check; each is pass/fail)
| Check | How | Fails if |
|---|---|---|
| Off-token color | Scan CSS and class names against the token list | Any color not in tokens |
| Decorative gradient | Find `linear-gradient`, `radial-gradient`, `bg-gradient-*` | No brand token or PR reason |
| Glass under text | Find `backdrop-filter` / `backdrop-blur-*` with low-alpha fill on elements holding text | Present without a contrast pass |
| Contrast on layers | Render, sample the lightest and darkest point under each text block | Below 4.5:1 (3:1 large) |
| Fallback | Look for `@supports` and reduced-transparency rules | Glass with no solid fallback |

**Moves** (see [conversation moves](../../../solutions-library/conversation-moves.md)). Here the "conversation" is the builder prompting the AI tool, or the checker reporting to the builder. The moves are adapted, and the fit is our judgment.
| Move | When, in this pattern |
|---|---|
| Ask one clarifying question | The builder asks for UI with no palette or token file: the tool asks for one before generating. |
| Offer choices: 2-4 options plus "Something else", free text open | The checker flags a gradient or glass panel: "Swap to brand tokens", "Keep it: record the brand reason", "Ask a designer", "Something else". |
| Admit uncertainty and show how to check | The checker cannot measure contrast (text over a video or a user photo): it says so and names the manual check. |
| Hand off to a person | The flag is about brand direction, not a rule break (see hand-off rule). |

**Don't over-correct.** Gradients and glass are not banned. A brand whose palette is purple should use purple. Apple and Microsoft design systems use glass-like materials on purpose (NN/g). Do not strip a brand gradient to pass a lint, and do not swap one stock look for another. The rule is "chosen and measured", not "never purple".

**Hand-off rule.** When the brief has no palette and no brand guide exists, or a flagged look is kept twice with "brand" as the reason, a human designer decides the palette and records it as tokens. The checker does not pick brand colors.

## 7. Metrics: how to spot it in production
Targets are starting points to tune on your own data, unless a source is given.
| Metric | Target | How to measure | Alert at |
|---|---|---|---|
| **Flagged generated screens shipped with no recorded reason** (primary, proposed) | Under 10% | Checker log per PR: flagged screens merged with no reason note, divided by generated screens reviewed | Over 20% |
| Off-token colors in generated code | 0 on main | Static scan of CSS and class names against the token list | Any |
| Text on glass or gradient below WCAG contrast | 0 | Rendered screenshot; sample the worst point under each text block | Any |
| Glass layers with no opaque fallback | 0 | Scan for `backdrop-filter` without a matching fallback rule | Any |
| Sampled "looks AI-made" rate | Track; set from baseline | Monthly blind review of 20 screens by people outside the team | Rising two months in a row |
| Brand gradients removed in error (counter-metric) | 0 | Designer reverts of checker-driven removals | Any |

### Detection signals (proposed, not yet calibrated)
Signals in generated code and the checker log. Treat them as proposed until checked against human-labeled screens.
| Signal | Where it shows | Counter-signal (what it could be instead) |
|---|---|---|
| Gradient built from `indigo`, `violet` or `purple` utilities or raw hex, no token | Generated CSS or class list | The brand palette really is purple and the token file says so |
| `backdrop-filter` with a low-alpha fill (for example `bg-white/10`) on an element that holds body text | Generated CSS plus DOM | A nav bar or modal over a solid background, with contrast measured |
| Colors defined as raw values; no import of the token file | Diff of the generated screen | A throwaway prototype marked as such in the PR |
| Same palette across unrelated projects from the same tool | Hash of color values per project | A team that shares one design system on purpose |

**Starter rule:** every generated screen uses only token colors, and any gradient or glass panel under text is flagged until it has a recorded reason and a contrast pass.

## 9. Common questions
### Why do all AI generated websites look the same?
With no direction, the model picks the most common choices in its training data. Anthropic describes this for its own model: Inter, purple gradients on white, minimal animation. Give the tool a palette and a rule file (section 5).

### Why does AI keep using purple gradients?
The usual explanation is that Tailwind UI demos used an indigo default that spread across tutorials the models learned from. That story comes from a single secondhand essay, so treat it as likely, not proven (section 4).

### How do I stop Cursor, v0 or Claude from using purple gradients?
Put your tokens and the rules block from section 5 in the tool's project instructions, and run the checklist before merge. Expect the tool to drift to a different stock look, and check for that too (rule 7).

### Is glassmorphism bad for accessibility?
Not by itself. Text on a translucent layer often falls below WCAG contrast where the background is light or busy. Measure the worst point, add an opaque fallback, and keep body text off glass (rules 4 and 5).

### Are gradients a sign of AI slop?
No. A gradient is a tell only when nobody chose it: it is off-brand, decorative and identical to every other demo. A brand gradient with a recorded reason passes (section 5, "Don't over-correct").
