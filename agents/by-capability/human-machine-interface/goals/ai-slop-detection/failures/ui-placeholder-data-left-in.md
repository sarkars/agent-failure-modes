**Frequency**: Common

## Issue: An AI-built page ships with filler nobody replaced: Lorem ipsum, "John Doe", example.com links, 555 phone numbers, "$XX" prices or TODO text.

> **One line:** The AI tool filled every empty slot with realistic-looking dummy content, the page looked done, and it went live; the fix is to mark missing content with one searchable marker and block any deploy whose built pages still contain placeholder strings.

## 1. In plain words
When you ask an AI tool for a landing page and don't give it your real content, it fills the gaps with stand-ins: Latin filler, "Dr. John Doe", "hello@example.com", "(555) 123-4567", "Acme Inc", "$XX/mo". The page looks finished, so it ships. Visitors then find a phone number that rings nowhere and a bio in Latin.

## 2. What it looks like
**Without the fix**
```
Builder: Build a landing page for Bright Smile Dental in Denver, with team, pricing and contact.
AI tool: Done! Your page has a hero, services, team, pricing and contact sections.
         Contact: (555) 123-4567 · hello@example.com · 123 Main St, Anytown, USA
         Team: Dr. John Doe, DDS. "Lorem ipsum dolor sit amet, consectetur adipiscing elit."
         Pricing: Cleaning $XX · Whitening $99/mo · "Join 10,000+ happy patients"
         Footer: © 2024 Acme Inc. All rights reserved.
Builder: Looks great. Deploying.
(Two weeks later a patient emails: "The phone number on your site doesn't work.")
```
**With the fix**
```
Builder: Build a landing page for Bright Smile Dental in Denver, with team, pricing and contact.
AI tool: The layout is built. You didn't give me 7 values, so I marked each one TODO-CONTENT
         instead of inventing it: phone, email, street address, dentist names, bios,
         cleaning price, patient count. Send the real values, or say "drop pricing".
Builder: (pastes phone, email, address and one dentist bio; says "drop pricing and the patient count")
AI tool: Filled 5 fields from your text, removed the pricing block and the count. 0 markers left.
Pre-deploy check: 0 placeholder hits in 9 pages. Deploy allowed.
```
The fixed tool marks gaps with one searchable marker, lists them, fills only from the builder's text, and a scan confirms zero hits before deploy.

## 3. Why it happens
- **The tool optimizes for a page that looks complete.** An empty slot looks broken in a preview, so the generator fills it with plausible stand-ins, and plausible stand-ins are exactly what a quick visual review misses. (Our reading.)
- **Real content lives outside the prompt.** The phone number, prices and staff names are in the owner's head or a spreadsheet, not in the request, so the tool has nothing true to put there.
- **Nobody scans the built output.** Teams check the page by looking at it on one screen. Filler hides in alt text, meta tags, the 404 page, footers and pages nobody clicks.

## 5. The fix
**The principle:** No value reaches a public page unless the builder supplied it; anything missing is marked, listed, and blocked at deploy.

**Do this**
1. **Zero unwaived hits at deploy.** The production build is scanned with the checklist below; any hit not on the waiver list blocks the deploy.
2. **Every fact traces to the builder.** Each phone, email, address, price, person's name, date and number on a public page appears in the prompt or the project's content file.
3. **Mark gaps, don't fake them.** When content is missing, the AI tool writes one searchable marker (for example `TODO-CONTENT: phone`) and lists every marker when it reports the page done.
4. **Keep intended examples reserved and waived.** Docs and demo screens use example.com, .org, .net or .example domains and 555-0100 to 555-0199 numbers, each listed on a waiver with the file and reason.
5. **Scan what ships, not only what you see.** Include alt text, page titles, meta descriptions, Open Graph tags, structured data, 404 and error pages, email templates and footers.
6. **Every link goes somewhere real.** No `href="#"` on navigation or call-to-action buttons, and no links or mailto addresses on example domains outside waived docs.
7. **Re-scan production.** Crawl the live site after each deploy and weekly with the same list.

**Reference design: pre-deploy placeholder checklist**
| Pattern family | What to match (case-insensitive) | Where it hides | Default action |
|---|---|---|---|
| Filler Latin | "lorem ipsum", "dolor sit amet", "consectetur adipiscing", "sunt in culpa" | Bios, cards, FAQs, footers | Block |
| Dummy people and companies | "John Doe", "Jane Doe", "John Smith", "Your Name", "Company Name", "Acme" | Team, testimonials, footer copyright | Block |
| Example domains and emails | example.com/.net/.org, ".example", "yourdomain", "user@domain", "test@" | mailto links, forms, footers, structured data | Block unless waived |
| Fictional or dummy phones | any "555" exchange, "123-456-7890", "000-000-0000" | `tel:` links, contact blocks, schema | Block unless waived |
| Dummy prices | "$XX", "$0.00", "$X/mo", identical prices on every tier | Pricing tables, checkout | Block |
| Marker text | "TODO", "TBD", "FIXME", "Insert", "Your tagline here", "coming soon", "under construction", text in [square brackets] | Anywhere | Block |
| Template numbers | stats like "10,000+ users" or "99.9% uptime" with no entry in the content file | Stats strips, hero | Ask the builder |
| AI leftovers | "As an AI language model", "Certainly! Here is", "I cannot fulfill this request", "Regenerate response" | Any generated copy | Block |
| Stale or default metadata | a copyright year that is not the current year; the starter template's default page title or favicon | `<title>`, footer, tab icon | Ask the builder |
| Placeholder media | images from placeholder-image services or files named "placeholder" | `<img>` sources, Open Graph image | Block |

**Prompt block for the AI tool**
```
Never invent names, phone numbers, emails, addresses, prices, counts or dates.
If I have not given you a value, write TODO-CONTENT: <field> in its place.
When you finish, list every TODO-CONTENT marker and ask me for the values or whether to drop the block.
Use example.com and 555-0100 to 555-0199 only on pages I call docs or demos.
```

**Moves** (see [conversation moves](../../../solutions-library/conversation-moves.md); here the conversation is the builder prompting the AI tool, or the checker reporting to the builder)
| Move | When, in this pattern |
|---|---|
| Ask one clarifying question | The AI tool is about to fill a field only the business knows (phone, price, staff name): it asks for that value once, or lists all missing fields in one message, instead of inventing it. |
| Offer choices: 2-4 options plus "Something else", free text open | The checker reports a hit: "Replace with the real value", "Remove this block", "Mark as an intended example", "Something else". |
| Admit uncertainty and show how to check | The checker cannot tell whether a number such as "10,000+ users" is real: it says so and points to the file and line, rather than calling it fake. |

**Don't over-correct.** Do not "fix" filler by having the AI invent realistic values: a made-up but believable phone number or patient count is worse than Lorem ipsum, and fabricated proof belongs to [fabricated social proof](./ui-fabricated-social-proof.md). Do not block real docs that show example.com requests; waive them. Do not silently delete a section that had filler; ask the builder whether to fill or drop it.

**Hand-off rule.** When a hit needs a value only the business owner knows (phone, prices, staff names, license numbers), the tool or checker stops and asks that content owner, and logs the open item; it never guesses.

**Framework used:** none yet. The word list draws on the TechWyse and Sitebulb checks and RFC 2606 (section 4) plus our judgment.

## 7. Metrics: how to spot it in production
Targets are proposed starting points to tune on your own data; no source sets them.
| Metric | Target | How to measure | Alert at |
|---|---|---|---|
| **Placeholder-free deploy rate** (primary) | 100% | Pre-deploy scan log: deploys with zero unwaived hits / all production deploys | Any production deploy with a hit |
| Placeholder hits on live pages | 0 | Weekly crawl of production with the same checklist | Any |
| Untraced facts on public pages | 0 | Phones, emails, prices and counts in built pages not found in the content file | Any |
| Open TODO-CONTENT markers at release | 0 | Count markers in the release build | Any |
| Waivers per release | Track; set from baseline | Count waived hits per release | Rising two releases in a row |
| Scan false-positive rate (counter-metric) | Under 10% | Monthly sampled review of 50 hits, labeled real or false | Over 20% |

### Detection signals (proposed, not yet calibrated)
| Signal | Where it shows | Counter-signal (what it could be instead) |
|---|---|---|
| Filler Latin in rendered body text | Built HTML text nodes | A design-system demo page or an article about Lorem ipsum |
| Reserved example domain in a link, form action or mailto | Built HTML attributes | API docs or a tutorial that uses example.com on purpose |
| A 555 number in a `tel:` link or contact block | Built HTML and structured data | A fiction or film page, or a waived demo |
| A name, price or count in generated copy that appears in no builder prompt or content file | AI tool session log compared with the build | The builder supplied it in a file the check did not read |
| `href="#"` on a call-to-action | Built HTML anchors | A script-handled control that should be a button element |

**Starter rule:** block a production deploy when the built pages contain any placeholder from the checklist that is not on the waiver list.

## 9. Common questions
### How do I check my website for Lorem ipsum before it goes live?
Scan the built output, not just the pages you click through, with the checklist in section 5. Include meta tags, alt text and the 404 page. Then crawl the live site after deploy, since SEO crawlers such as Sitebulb include a Lorem ipsum check.

### Why does v0, Lovable or Bolt put "John Doe" and 555 numbers in my page?
The tool fills empty slots so the preview looks complete, and it does not know your real details. Tell it not to invent values and to mark gaps instead (the prompt block in section 5).

### Is it OK to leave example.com in production?
Only on docs or demo pages where it is meant as an example; RFC 2606 reserves it for that. In a contact link or form it is a dead end, so the scan should block it there.

### Is "10,000+ happy users" placeholder or fake social proof?
If you never supplied the number, it is unreplaced filler, and this page's scan flags it. Whether a real number is honest and how to show proof is covered in [fabricated social proof](./ui-fabricated-social-proof.md).

### Does leftover placeholder text hurt SEO?
Sitebulb, a crawler vendor, calls such pages "under-optimized from an SEO standpoint", and TechWyse mentions possible duplicate content issues. I found no search engine statement on it, so treat this as vendor opinion.

### Should I just ask the AI to use realistic fake data instead?
No. Realistic fake data is harder to spot and can mislead visitors. Use one obvious marker and fill it with real content.
