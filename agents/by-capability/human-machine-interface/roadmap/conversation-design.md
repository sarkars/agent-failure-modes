# Roadmap: Conversation Design, Refusals, and Error Recovery

> **Family goal:** A conversation moves the way a skilled person's does: it follows what the person means, asks only what it needs, says no in a way that still helps, and owns its mistakes.

**How these were chosen.** The first roadmap focused on skills, channels, and agent types. This file adds the mechanics of the exchange itself: following references and corrections, asking and confirming, refusing, and recovering. Over-refusal has a body of public benchmarks (for example XSTest, with 250 hand-written prompts, and OR-Bench, with about 80,000), which I know only through search summaries, so check them before citing. I found no systematic measure of preachy tone; RF-03 and RF-04 need research before they are written.

Flags: **V** verified source · **R** needs research · **L** legal review · **E** expert review. **In the library today:** **Covered** = a pattern already exists · **Extends** = an existing pattern covers the technical failure and a new one would add the experience or design angle and a fix · **New** = no matching pattern found by file-name and keyword search (re-check before writing) · **Written** = an HMI pattern exists. **Root cause:** Model · Reliability · Business context · Governance. **Better model alone?** Yes / Partly / No. Both columns are my judgments, not measurements. See the [roadmap README](README.md).
