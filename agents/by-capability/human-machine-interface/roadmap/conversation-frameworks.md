# Roadmap: Conversation Framework Failures

> **Family goal:** The bot uses proven conversation structures (for selling, supporting, matching a user's style, and delivering hard news) instead of improvising every exchange.

**How to read the framework claims.** These frameworks come from human-to-human practice. None has been tested on chatbots in the sources I found. Each pattern below treats a framework as a hypothesis to test, not a proven fix. See the [framework register](README.md#framework-and-source-register) for what I verified.

Flags: **V** verified source · **R** needs research · **L** legal review · **E** expert review. **In the library today:** **Covered** = a pattern already exists, so no new one is planned · **Extends** = an existing pattern covers the technical failure and a new one would add the experience or design angle and a fix · **New** = no matching pattern found by file-name and keyword search (re-check before writing). See the [roadmap README](README.md). **Root cause:** Model = a stronger model plausibly reduces it · Reliability = state, verification, enforcement, evals, latency · Business context = your data, entitlements, rules, workflows, UX · Governance = incentives, law, and decisions. **Better model alone?** Yes / Partly / No. These two columns are my judgments (one label per row), not measurements.

## C. Matching the customer's style and language
Grounding (verified): people in conversation tend to match each other's language style turn by turn, and the authors link this to engagement, not necessarily liking (Niederhoffer & Pennebaker, 2002). Nonconscious mimicry was found to make interactions smoother and raise liking in lab settings, though a replication was reported to be only partly successful (Chartrand & Bargh, 1999).
