# Roadmap: Failures by Agent Type, and Cross-Agent Additions

> **Family goal:** Each kind of agent being built today is checked for the failures that matter most for its job, starting with the types that are most widely adopted.

**How these were chosen.** I started from adoption surveys. They disagree on ranking, but the picture is consistent: coding agents are the most widely adopted (nearly 90% of surveyed organizations use AI for coding in one report), customer service and research and data analysis lead in a builder survey (26.5% and 24.4%), internal process automation and data entry are common, IT and security agents are widespread, and healthcare estimates vary widely (4% to 18%). Sources are surveys from Anthropic, LangChain, and Zapier, plus secondary roundups, and I did not verify their methodology.

**One gap worth knowing about.** The library's own Code Agent area lists four goals (generation, bug fixing, refactoring, review), all marked "Planned", with no pattern files. Coding agents are the largest agent type, so they come early in the [execution plan](execution-plan.md).

**Notes.** MA-02 replaces an item I had earlier that duplicated OV-12. XA-01 to XA-03 come from the demand research: the top customer pain point (bots that don't understand), the top builder barrier (quality and how it's measured), and the lack of ways to report bad behaviour. Every pattern in this file is a **candidate**; research each before writing.

Flags: **V** verified source · **R** needs research · **L** legal review · **E** expert review. **In the library today:** **Covered** = a pattern already exists · **Extends** = an existing pattern covers the technical failure and a new one would add the experience or design angle and a fix · **New** = no matching pattern found by file-name and keyword search (re-check before writing) · **Written** = an HMI pattern now exists. **Root cause:** Model · Reliability · Business context · Governance. **Better model alone?** Yes / Partly / No. Both columns are my judgments, not measurements. See the [roadmap README](README.md).
