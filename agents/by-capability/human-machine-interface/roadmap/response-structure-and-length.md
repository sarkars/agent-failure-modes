# Roadmap: Response Structure, Length, and Closers

> **Family goal:** Replies are shaped so people can read, act on, and answer them, and short messages like "ok" and "bye" get the response the moment calls for.

**Grounding (verified through search):**
- **Length drift:** reward models used to train assistants track output length, and a length-only reward reproduced most of the downstream gains in the study (Singhal et al., 2023). That's one reason replies run long.
- **"Okay" is not just agreement:** conversation analysis finds "okay" can mark a transition to a new activity (Beach, 1993) or serve as a neutral acceptance token (Oloff, 2019). Treating every "ok" the same loses that information. I found **no study of how chatbots should handle "ok", thanks, or goodbye**.

**Already in the library:** verbosity and call endings for voice ([verbosity despite brevity instructions](../../speech-and-audio/goals/conversation-flow/failures/verbosity-despite-brevity-instructions.md), [graceless call ending](../../speech-and-audio/goals/conversation-flow/failures/graceless-call-ending.md), [premature call ending](../../speech-and-audio/goals/conversation-flow/failures/premature-call-ending.md)); [conversation depth mismatch](../../../by-use-case/agent-interaction/goals/conversation-quality/failures/conversation-depth-mismatch.md); silent output truncation ([output truncation silent](../../../cross-cutting/operations/goals/input-output-handling/failures/output-truncation-silent.md)); and, for support, [closing a ticket on a polite cue](../../../by-use-case/support-services/goals/issue-resolution/failures/premature-ticket-closure-from-politeness-cue-misread-as-resolution-confirmation.md). Chat-specific structure and closer handling are mostly gaps.
