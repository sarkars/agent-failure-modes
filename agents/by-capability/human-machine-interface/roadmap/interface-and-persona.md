# Roadmap: Persona and Tone, Onboarding, Chat Interface, Accessibility, and Multimodal Input

> **Family goal:** The assistant keeps a consistent, fitting character; people know how to start and can use every part of it; and what they type, speak, or show is read properly.

**How these were chosen.** These are interface-level failures that the first roadmap did not cover: tone and persona, the blank-box problem, the mechanics of a chat window, accessibility, and non-text input. Evidence is thin in places. For onboarding I read the Nielsen Norman Group's site-chatbot research and an arXiv paper on question suggestions only through search summaries; the accessibility items rest on practitioner write-ups, not peer-reviewed studies. Treat those rows as candidates and research them before writing.

Flags: **V** verified source · **R** needs research · **L** legal review · **E** expert review. **In the library today:** **Covered** = a pattern already exists · **Extends** = an existing pattern covers the technical failure and a new one would add the experience or design angle and a fix · **New** = no matching pattern found by file-name and keyword search (re-check before writing) · **Written** = an HMI pattern exists. **Root cause:** Model · Reliability · Business context · Governance. **Better model alone?** Yes / Partly / No. Both columns are my judgments, not measurements. See the [roadmap README](README.md).
