# Stale Training Knowledge Overrides Live Dosage-Guideline Lookup

## Issue: An Agent Drafting a Progress Note or Medication Order Summary That Has Access to a Live Formulary/Dosage-Guideline Lookup Tool Skips or Discounts the Tool's Current Result and Instead Writes the Dosing Language From the Guideline Value Memorized in Its Training Data, Which Predates a Since-Published Revision to the Recommended Dose, Producing a Note That Documents an Outdated Regimen as if It Were Current Practice

**Frequency**: Occasional

**Symptoms**
- Generated note states a weight-based or renal-adjusted dose that matches a superseded version of a clinical guideline rather than the version currently returned by the connected formulary/guideline tool
- The agent's tool-call trace shows the live guideline lookup was executed and returned the updated value, but the generated note text reflects the older figure instead
- Discrepancy is only caught when a pharmacist or attending cross-checks the note against the current formulary reference directly
- Same outdated figure recurs across multiple notes generated by the same agent instance for the same drug, indicating a systematic default rather than a one-off transcription slip
- Re-running the identical note-generation request after explicitly instructing the agent to "use only the tool result, not prior knowledge" produces the correct, current dose

**Example**
```
Hospital's order-summary agent drafts a discharge note for a patient started on a renally-dosed antibiotic
Agent calls the connected formulary tool, which returns the current renal-dosing table (revised six months ago to lower the threshold creatinine clearance cutoff)
Generated note instead documents the dose using the pre-revision cutoff that matches what was common in training-era literature
Tool-call log confirms the current table was successfully retrieved and available in context at generation time
Pharmacist review catches the mismatch only because the documented dose doesn't match what was actually ordered in the EHR
Investigation finds the agent's note-drafting step treated the live lookup as a formality and defaulted to its memorized dosing convention when phrasing the note
```

**Contributing Factors**
- No explicit system instruction requiring the agent to treat a successful live guideline-tool result as overriding any internally recalled dosing convention
- Guideline revision was incremental (a changed cutoff value, not a renamed drug or new indication), so the agent's fluent, confident phrasing gives no surface signal that it diverged from the tool result
- Drafting step composes note language from a blend of the tool result and the model's general medical knowledge rather than being constrained to quote the tool output verbatim for dosing figures
- No automated post-generation check diffing dosing values stated in the note against the exact value returned by the formulary tool call in the same session

---

## Mitigation Strategies

1. **Verbatim-Value Constraint for Dosing Figures**: Require any numeric dosing, threshold, or cutoff value in generated documentation to be copied directly from the tool's returned payload rather than composed by the model, with the tool's exact string inserted via template rather than free generation
2. **Post-Generation Diff Check**: Automatically compare every numeric clinical value in the generated note against the corresponding value in the same session's tool-call log and flag any mismatch before the note is finalized
3. **Guideline-Revision Recency Flag**: Have the formulary tool surface a "revised on [date]" marker in its response and require the agent to acknowledge the revision date in its reasoning trace before drafting dosing language
4. **Periodic Training-Knowledge Audit**: Run scheduled test prompts against known-revised guidelines to detect whether the agent's default behavior has drifted back toward memorized values after a model or prompt update

### Metrics
- Rate of generated notes whose stated dosing values do not exactly match the formulary tool's returned value in the same session
- Number of pharmacist or attending corrections attributable to outdated dosing language in agent-drafted notes
- Time elapsed between a guideline revision going live in the formulary tool and the agent's output reliably reflecting it

### Alerts
| Alert | Condition | Severity | Response |
|-------|-----------|----------|----------|
| Dosing value mismatch | Note's stated dose differs from the same-session tool-call's returned value | P1 | Block note finalization; route to pharmacist review |
| Guideline drift recurrence | Same outdated value appears across multiple notes following a known guideline revision | P2 | Audit drafting prompt; reinforce verbatim-value constraint |
| Tool result ignored | Tool-call trace shows a successful lookup with no corresponding reference in generated text | P3 | Review generation pipeline for silent tool-result discard |
